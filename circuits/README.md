# Thornado Withdrawal Circuits

This directory contains the reference Circom withdrawal circuit. The Rust
implementation uses a BN254 Groth16 withdrawal backend in
`crates/thornado-core/src/stark.rs`, matching the circuit-specific Groth16
setup used by this proof family rather than a transparent STARK/Bulletproof
backend.

The circuit proves:

- the prover knows `nullifier` and `secret`;
- `commitment = Pedersen(nullifier || secret)`;
- `nullifierHash = Pedersen(nullifier)`;
- `commitment` is included in a MiMC Merkle tree with public `root`;
- public withdrawal fields are bound into the proof.

Public signal order is:

1. `root`
2. `nullifierHash`
3. `recipient`
4. `relayer`
5. `fee`
6. `refund`

Compile the constraint system from the repository root:

```sh
npm install circomlib snarkjs
npx circom circuits/withdraw.circom --r1cs --wasm --sym -o build/circuits
```

The checked Rust withdrawal path is:

- backend: Groth16 over BN254 using arkworks;
- trusted setup: circuit-specific Groth16;
- witness hiding: Groth16 proof system;
- note hash: MiMC sponge over BN254 field inputs;
- Merkle tree: fixed-depth MiMC sponge tree.

The Circom files remain as a reference artifact, but the checked Rust verifier
does not consume Circom R1CS or snarkjs output yet. The in-code setup uses
fresh local randomness for development; production should replace it with
audited proving/verifying keys generated by a real MPC ceremony.

The Rust path now uses the same MiMC sponge family as the reference Merkle
circuit, but it has not yet implemented circomlib Pedersen for
`commitment/nullifierHash`.

The circuit source is intentionally minimal and should be treated as an
implementation fixture until production proving and verifying keys are
generated and pinned.
